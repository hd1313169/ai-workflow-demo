# Design

## Context

見 proposal.md - Why。此資料夾為展示用副本、無 git、可原地改寫。先前去識別化已將導覽品牌與主色換掉，但只處理兩個報表頁畫面。頁面 JS 與 `components.js` 有以中文字串判斷行為的邏輯，替換必須成組。

## Goals / Non-Goals

**Goals:**
- 版控追蹤檔案零命中禁用詞；`lint:brand` 可在本機與 CI 重複執行。

**Non-Goals:**
- 不改 `fb-` 元件前綴與程式識別字（非識別資訊）。
- 不重新設計畫面或互動；不再換色。

## Decisions

**1. 禁用詞清單存於 `.brand-denylist.txt`（gitignore），CI 用 Secret 注入。**
清單本身就是識別資訊，不能進 repo。*替代*：清單用雜湊比對 → 無法做子字串搜尋，捨棄。

**2. `lint:brand` 實作於 `build.mjs`，沿用 `lint:tokens` 模式，可帶目錄參數。**
維持零相依；同一指令日後也用來掃 Storybook 產物。比對不分大小寫。

**3. 刪除 archive 與已完成未歸檔的 change，而非改寫。**
archive 約 30 份文件且含舊新對照表，改寫易漏、對照表改寫後無意義。保留並改寫 `openspec/specs/**`。

**4. 刪除 Figma node ID 註解與 `figma-export.json`。**
node ID 單獨無害，但組合後可定位；展示不需要。`components.md` 保留元件說明，移除 node 欄。

**5. 術語沿用既有對照方向（境內／境外客戶、集團戶、客戶類型…），虛構公司名以中性名稱（如「北辰科技」）替代。**
對照表只存在於實作者本機，不寫入任何追蹤檔。

**6. 替換順序：先程式邏輯與其成對字串，再文案，最後文件。**
每批替換後以瀏覽器開頁驗證，降低成組替換遺漏造成的功能損壞。

## Risks / Trade-offs

- [成組替換遺漏導致功能壞] → 每頁手動冒煙測試，主控台零錯誤。
- [禁用詞清單不完整] → 清單先由全庫掃描結果建立，再加上變形（英文、大小寫、網域）；最後人工瀏覽全部頁面一次。
- [刪除 archive 失去演進紀錄] → 已接受；此為展示副本。

## Migration Plan

原地修改，不可回滾（無 git）。如需保險，實作前先將整個資料夾另存一份壓縮檔於 repo 外。
